## How to read this

**Bins.** Every item lands in exactly one:

| Bin | Meaning |
|-----|---------|
| Habit | Adopted by changing how we work or what a template or role page says; nothing to build |
| Bought | A product does it (Spec Kit, GitHub Issues, Actions, rulesets, CODEOWNERS, Logfire, Cursor CLI); we only configure |
| Glue | Small code or workflow files we write around bought parts |
| Retire | Removes or shrinks a Wave 1 piece |
| Later | Goes to the product, infrastructure or tooling backlog |
| Done | Already settled during the retro |

**Ranks.** One test: what Wave 1.5 needs to deliver a factory that Smart Writer V2 can be built on (item 70). That means one real order runs end to end on the new path, unattended, measured and guarded against irreversible harm, in all three lanes, with the Wave 1 machinery it replaces removed and the rulebooks describing the new factory.
- **Must:** without it the factory is not usable as one whole, or is unsafe.
- **Should:** clearly worth it; the factory still works without it.
- **Could:** nice; first to go below the line.

**Estimates** are in agent-hours, likely and pessimistic (item 1). They are the orchestrator's judgement and are **not calibrated**: the Wave 1 baseline (item 85) does not exist yet. Governor time is listed separately.

## 1. The target in one paragraph

Work enters as a GitHub issue (an order; its tasks are sub-issues) with a lane: light, normal or full. A small GitHub Actions workflow starts the lab's Spec Kit workflow for that issue. Spec Kit runs the steps in order: for the full lane intent, spec, reviews, plan with the architecture phase, tasks and test review; for every lane build, check and cross-family review; then merge. Agents run headless through the Cursor CLI with a model named per step; reviewers run on another model family. Agents write files in about six fixed formats; code validates them at once, allows one repair, and writes every record, issue update, push and pull request itself. When a decision is needed the workflow pauses, the governor is asked through an issue, and code records the lock and resumes the run. Deadlines, two automatic resumes and an outside watchdog keep runs from stalling silently. Each step reports model, role, work item, time and (where the runtime gives it) tokens to Logfire, so a scorecard can be computed. Merges to `main` need a pull request, green checks and an accepted cross-family review, enforced by GitHub rulesets. The Wave 1 queue (orders, amendments, claims, handoffs), most of the `factory` command, 3 of 4 editor hooks and about two-thirds of the checks are removed.

## 4. Roll-up and a proposed good-enough line

| Band | Agent-hours (likely / pessimistic) | Contents |
|------|-----------|----------|
| Must | 57 / 120 | C1–C19 Must parts |
| Should | 11 / 23 | Copilot fallback; scoped re-review and competition seat; check track record; scorecard, drift signal and baseline; open-decisions list; acceptance view |
| Could | 3 / 6 | Burn chart; import-layer lint; exemplars |

Governor time, outside the agent estimate: settings and secrets (rulesets, CODEOWNERS, the App, `CURSOR_API_KEY`), review of the rulebook rewrite, decisions during the trial. Roughly 3 to 5 hours.

**Proposed line: Must plus Should** (about 68 likely, 143 pessimistic). The Should items are cheap and most of them are what makes the scorecard and the governor's view real; without them the factory runs but is half-blind.

**A tension to settle at the line:** item 78 says Wave 1.5 is small, and the governor's coherence requirement (one usable whole, including removals) makes it larger than the 1.5 to 2 days the orchestrator suggested on 2026-10-07. The Must band alone is roughly Wave 1's order of size in agent work, not a patch. Two ways to keep it honest: hold the line at Must plus Should and phase it with a stop point after the trial (section 5), or cut C15 and C19 to a later sprint and accept two ways of working for a while (the orchestrator recommends against this: it breaks the coherence requirement).

**The trial gate.** The survey's strongest case against Spec Kit: if the trial shows more than a few days of reliability glue, switch to AI-SDLC. The trial covers the riskiest parts of C4, C5, C6, C7, C8, C12 and C13, roughly 20 likely agent-hours. A stop point after it re-estimates the rest before the bulk is spent.

## 6. Architecture points found while sorting

1. **Pull requests opened by code do not trigger checks** when made with the default Actions token; GitHub suppresses workflow runs for events caused by that token. Code that opens pull requests (item 91) needs the GitHub App's token, or a personal token. Hence keeping and finishing the App (3a). Add to the trial questions.
2. **Item 33 and item 31 disagree** on the plain-decision check: one lists it as blocking, the other says word lists only warn. Proposed reading: block on structure (options with labels, a recommendation, the schema), warn on banned words.
3. **Per-run token caps cannot be enforced on Cursor's individual plans**, which report no per-run usage (item 82). What code can enforce is time per step and per order. Since estimates are in agent-hours, a time cap at a multiple of the estimate matches item 84 to the letter; token caps apply only where a runtime reports tokens. Disclosed here, not substituted silently.
4. **Changeover without two systems.** Item 76 says a known-good factory runs the sprint. The Wave 1 process runs Wave 1.5 until the new path finishes the trial order and one light change; at a named cutover the old queue stops taking work, and C19 removes it. No order is ever handled by both.
5. **The Spec Kit upgrade may overwrite the lab's template overrides** under `.specify/templates/`. Check before upgrading; part of trial question 11.
